# Quant Guardian 지수 타이밍 TRD

## 1. 시스템 구성

```text
Yahoo 일봉 데이터
  -> quant_guardian.py
     -> 기술지표·행동·목표비중·백테스트 CSV
  -> build_dashboard.py
     -> dashboard.html + daily.json + report.md/html
  -> GitHub Actions
     -> GitHub Pages 배포
     -> telegram_notify.py
        -> Telegram Bot API
```

정적 사이트 구조이므로 웹 서버나 데이터베이스가 없다. 민감한 봇 토큰과 채팅 ID는 GitHub Actions Secrets에서만 읽는다.

## 2. 데이터

- 공급원: Yahoo Finance chart API
- 주기: 1일봉
- 필드: Open, High, Low, Adjusted Close, Volume
- 분할·배당 조정을 맞추기 위해 Open/High/Low도 Adjusted Close 비율로 보정한다.
- 캐시: `data/cache/yahoo_<ticker>.csv`
- 화면 기준: 각 ETF의 마지막 이용 가능한 미국장 마감일
- 실시간성: 장중 가격 미지원

데이터 수집 실패 시 기존 캐시가 있으면 캐시를 사용할 수 있다. 새 설치에서 필수 ETF 캐시가 없으면 `--refresh` 실행이 필요하다.

## 3. 지표 엔진

`technical_snapshot()`이 ETF 하나의 OHLCV를 받아 한 시점의 지표와 행동을 반환한다.

### 3.1 추세 40점

- 종가 > SMA200: 10
- SMA50 > SMA200: 6
- 종가 > SMA50: 4
- SMA20 > SMA50: 4
- EMA12 > EMA26: 4
- MACD > Signal: 4
- 일목 구름대 위치: 최대 5
- 전환선 > 기준선: 2
- ADX ≥ 20 및 +DI > -DI: 1

### 3.2 모멘텀 25점

- 12-1개월 모멘텀: 최대 10
- 6개월 수익률: 최대 6
- 3개월 수익률: 최대 4
- SPY 대비 6개월 상대강도: 최대 3
- 1개월 수익률 양수: 2

연속값은 넓은 구간에서 0과 최대점 사이로 제한한다. 단일 임계값 직전·직후의 급격한 점수 변화를 줄이기 위한 방식이다.

### 3.3 진입 타이밍 20점

- RSI14: 최대 6
- 볼린저밴드 내 위치: 최대 4
- SMA20 대비 ATR 이격: 최대 4
- 스토캐스틱 %K: 최대 3
- 20일 돌파·거래량·OBV: 최대 3

단기 과열은 RSI, 볼린저 상단 이탈, ATR 이격, 스토캐스틱 중 두 개 이상이 동시에 충족되거나 극단값이 나온 경우로 제한한다.

### 3.4 위험 15점

- 63일 연환산 변동성: 최대 6
- 최근 1년 최대낙폭: 최대 4
- 가격 대비 ATR: 최대 3
- VIX: 최대 2

점수가 높을수록 최근 관측 위험이 상대적으로 낮다는 뜻이며 손실이 없다는 뜻은 아니다.

## 4. 행동 규칙

- `신규매수`: 장기 상승 추세, 75점 이상, 과열 아님, 눌림 또는 거래량 돌파 확인
- `분할매수`: 장기 상승 추세, 65점 이상, 과열 아님
- `보유·추격매수 대기`: 장기 상승 추세지만 복수 과열 조건 충족
- `보유·관찰`: 장기 추세가 완전히 무너지지 않았으나 진입 확인 부족
- `비중축소`: 52점 미만 또는 200일선 아래
- `매도·대기`: 가격이 200일선과 일목 구름대 아래이며 40점 미만

## 5. 시장 판단과 배분

SPY 점수 55%, QQQ 점수 45%를 합산한다. 두 지수가 모두 200일선 아래면 점수를 34점 이하로 제한하고, 하나만 아래면 59점 이하로 제한한다. VIX가 설정 상단 이상이면 8점을 차감한다.

목표 주식형 비중:

```text
buy        100%
accumulate  90%
hold        75%
trim        50%
exit         0%
```

영문 프로필 키는 내부 설정 호환용이며 웹과 텔레그램에는 한글 행동만 표시한다.

주식형 선택은 종합점수 순 상위 두 개다. 1순위가 섹터 ETF면 2순위는 반드시 핵심 지수에서 선택한다. 1순위 기본 비중은 주식형 예산의 60%이며 섹터 ETF는 전체 자금의 50%로 제한한다.

## 6. 백테스트

- 시작일: `config.toml`의 `backtest_start_date`
- 신호 시점: 월말까지 이용 가능한 일봉
- 보유 수익률: 다음 달 월간 수익률
- 거래비용: 이전 목표비중과 새 목표비중 차이의 절반을 회전율로 계산해 `transaction_cost_bps` 적용
- 대기자금: SGOV의 짧은 역사 때문에 SHY 사용
- 불완전한 현재 월: 제외
- 벤치마크: 같은 월의 SPY, QQQ

제약: 현재 ETF 목록을 과거부터 알고 있었다는 선택 편향, ETF 상장 전 지수 대체 부재, 환율·세금·슬리피지 차이가 남는다.

## 7. 배포와 알림

- GitHub Actions 일정: 평일 22:30 UTC, 한국 시간 다음 날 07:30
- 순서: 테스트 → 최신 데이터 → HTML/JSON/CSV 생성 → Pages 배포 → Telegram 전송
- `main` 코드 푸시는 사이트만 배포하고 Telegram은 보내지 않는다.
- 수동 배포는 `send_telegram`을 선택한 경우에만 Telegram을 보낸다.
- 필수 알림 시크릿: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
- 선택 알림 시크릿: `PORTFOLIO_VALUE_KRW`

`PORTFOLIO_VALUE_KRW`는 Telegram 작업에서만 읽으며 `daily.json`과 공개 페이지에 기록하지 않는다. 웹 총 투자금은 브라우저 `localStorage`에만 저장한다.

- 텔레그램 한글 행동, 원화 계산, 예전 용어 미노출 확인
