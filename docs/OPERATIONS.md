# Quant Guardian 사용·운영 설명

## 매일 보는 방법

1. `오늘 할 일`을 읽는다.
2. `주식형 목표 비중`을 현재 계좌의 주식형 비중과 비교한다.
3. 우선 ETF의 `실행 기준`을 확인한다.
4. 목표 비중이 달라졌더라도 일일 노이즈를 줄이기 위해 주 1회 이내로 주문을 모은다.
5. 목표 평가액에서 현재 보유 평가액을 빼 실제 매수·매도 검토액을 계산한다.

## 행동 뜻

- `신규매수`: 장기 추세와 진입 조건이 함께 양호하다. 표시된 목표금액을 분할해 검토한다.
- `분할매수`: 상승 추세지만 확인이 더 필요하다. 절반 먼저, 다음 종가 조건 통과 후 나머지를 검토한다.
- `보유·관찰`: 보유분은 유지하고 추가매수 조건을 기다린다.
- `보유·추격매수 대기`: 추세는 좋지만 단기 이격이 크다. 보유하되 새 매수는 기다린다.
- `비중축소`: 신규매수를 중단하고 목표 비중을 넘는 부분을 나눠 줄인다.
- `매도·대기`: 장기 하락 조건이다. 주식형 비중을 없애고 회복 조건까지 기다린다.

## 웹의 원화 금액

`목표 비중` 탭에서 총 투자 가능 금액을 입력한다. 예를 들어 총 1,000만 원이고 SPYM 목표가 40%면 목표 평가액은 400만 원이다.

```text
실제 매수 검토액 = 400만 원 - 현재 SPYM 평가액
```

입력값은 현재 브라우저에만 남는다. 공용 PC에서는 사용 후 `금액 지우기`를 누른다.

## 텔레그램 원화 금액

GitHub Actions Secret에 아래 항목을 선택적으로 추가한다.

```text
Name: PORTFOLIO_VALUE_KRW
Secret: 총 투자 가능 금액(쉼표 없이)
```

예: `10000000`. 설정하지 않으면 비중만 온다. 총 투자금은 공개 웹 파일에 들어가지 않는다.

## 신호별 실제 확인

### 신규매수·분할매수

- 미국장 종가 기준인지 확인한다.
- ETF가 200일선과 일목 구름대 위인지 확인한다.
- 실행 문구의 20일선·50일선 조건을 확인한다.
- 한 번에 목표금액 전부를 주문하지 않는다.

### 보유·추격매수 대기

- 보유분을 자동으로 팔라는 뜻이 아니다.
- RSI가 낮아지거나 가격이 20일선 근처로 돌아올 때까지 추가매수를 기다린다.

### 비중축소·매도·대기

- 현재 평가액이 새 목표액보다 큰지 먼저 계산한다.
- 하루 장중 하락만 보고 실행하지 않고 마감 종가와 다음 주 확인 조건을 사용한다.

## 자동 갱신 확인

GitHub 저장소에서 다음 경로를 연다.

```text
Actions -> Build and Deploy Quant Guardian
```

초록색이면 테스트, 데이터 갱신, 페이지 배포, 텔레그램 단계가 성공한 것이다. 빨간색이면 해당 실행을 열어 실패한 단계 이름을 확인한다.

## 로컬 점검

```powershell
python -m unittest discover -s tests -v
python launch_dashboard.py --refresh --no-open
python quant_guardian.py signal
```

생성 파일은 `output/dashboard.html`이다.

## 현재 확정되지 않은 운영값

- 실제 총 투자 가능 금액
- 사용자가 허용하는 최대 계좌 낙폭
- 매일 알림과 신호 변경일 알림 중 선호 방식
- 실제 보유량 입력·동기화 여부

이 값들이 정해지기 전에는 프로그램이 임의의 개인 투자금이나 손실 한도를 가정하지 않는다.
