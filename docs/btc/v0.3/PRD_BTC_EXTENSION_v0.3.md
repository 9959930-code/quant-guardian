# PRD — Quant Guardian Bitcoin Cycle Signal Extension

- 문서 버전: `0.3`
- 작성 기준일: `2026-08-09`
- 상태: **REQUIREMENTS BASELINE — 반감기 필수 / 전략 연구·모의운영 전**
- 대상 프로젝트: `Quant Guardian`
- 대상 저장소: `9959930-code/quant-guardian`
- 관련 문서: `TRD_BTC_EXTENSION_v0.3.md`, `BTC_STRATEGY_RESEARCH_DESIGN_v0.3.md`, `ACCEPTANCE_TESTS_BTC_EXTENSION_v0.3.md`, `BTC_SHADOW_MODE_PLAN_v0.3.md`, `SOURCES_BTC_STRATEGY_v0.3.md`
- 통합 대상: 최신 로컬 저장소의 `docs/PRD.md`, `docs/TRD.md`, `docs/OPERATIONS.md`

> 이 문서는 비트코인 기능이 무엇을 해야 하는지를 정의한다.  
> 비트코인 반감기 정보는 모든 배포 가능한 전략의 필수 입력이다. 다만 반감기 하나만으로 매수·매도하지 않고 가격·추세·온체인·변동성·원화시장 정보를 함께 확인한다.  
> 실제 백테스트와 1개월 모의운영을 통과하기 전에는 후보 임계값과 비중을 실전 확정값으로 취급하지 않는다.

---

## 1. 제품 한 줄 요약

Quant Guardian의 미국 ETF 기능을 유지하면서, **비트코인의 반감기 사이클을 중심축으로 가격·추세·온체인·위험·업비트 원화시장 데이터를 종합해 언제 몇 %를 매수·보유·축소·매도할지 설명하는 공개 대시보드와 텔레그램 알림 기능**을 추가한다.

자동주문은 하지 않는다.

### 2.1 중요한 해석

- `BTC 최대 100%`는 전체 금융자산이 아니라 별도로 정한 BTC 전용자금 안에서의 100%다.
- 기본예산 500만원은 고정값이 아니다. 사용자는 300만원·1,000만원 등으로 언제든 바꿀 수 있다.
- 예산 변경은 **개인 목표금액만 다시 계산**하며 시장 신호, 목표비중, 백테스트 결과를 바꾸지 않는다.
- `MDD -50% 하한`은 손실 보장이 아니라 연구 후보를 거르는 경계다. MDD를 음수로 저장하므로 `MDD >= -50%`인 후보만 통과하며, 실전 전략은 가능하면 -35~-45% 범위를 먼저 지향한다.
- 1개월 모의운영 중에는 실제 주문을 권하지 않고 가상 체결만 기록한다.

## 2.2 연구 근거를 제품 요구사항으로 반영하는 원칙

- 반감기는 프로토콜상 210,000블록마다 발생하는 확정적 공급 이벤트이지만, 가격반응의 크기와 시점은 확정적이지 않다.
- 과거 반감기별 수익·변동성 반응이 동일하지 않고 최근 사이클에서 반응이 약해졌다는 연구도 있으므로, 반감기를 **필수 국면 변수**로 사용하되 단독 매매명령으로 사용하지 않는다.
- 기술적 매매규칙은 인샘플 성과가 좋아도 Bitcoin 아웃오브샘플에서 약해지거나 거래비용에 민감했다는 연구가 있으므로, 지표 수를 늘리는 방식보다 워크포워드·비용·민감도 검증을 우선한다.
- 온체인 지표는 Bitcoin 고유 정보를 제공하지만 공급자 정의·주소 군집화·데이터 개정의 영향을 받으므로, 지표별 출처·가용시각·개정 이력을 기록한다.
- 실전판은 설명 가능한 상태 머신을 기본으로 하고, 머신러닝은 동일 데이터로 비교하는 연구용 challenger로만 시작한다.

## 3. 제품 목표

1. 최신 확정 BTC 일봉으로 현재 행동을 한국어로 표시한다.
2. 반감기 위치를 블록 높이 기준으로 계산하고 모든 행동 설명에 포함한다.
3. 가격·추세·온체인·변동성·업비트 원화시장 신호를 독립 영역으로 평가한다.
4. 상태별 목표 BTC 비중과 사용자가 선택한 예산 기준 목표금액을 계산한다.
5. 전략 수익률, BTC 단순보유 수익률, 현재 신호 이후 수익률을 같은 기간 기준으로 비교한다.
6. 개인 보유정보를 입력한 경우 브라우저 안에서만 개인 평가액과 수익률을 계산한다.
7. 매수전략과 매도전략을 독립적으로 비교하고, 핵심+전술 구조를 포함한다.
8. 미래참조·과최적화·거래비용 누락을 방지한 워크포워드 백테스트를 수행한다.
9. 기존 미국 ETF 기능·사이트·텔레그램을 깨뜨리지 않는다.
10. 30개 확정 일봉의 모의운영을 통과한 뒤에만 실전 모드 전환을 검토한다.

## 6. 사용자 예산 선택과 개인 계산

### 6.1 기본 원칙

공개 전략은 예산과 무관하게 `목표비중`을 만든다. 사용자의 브라우저가 그 비중을 개인 예산에 적용한다.

```text
공개 신호: 목표비중 40%
사용자 A 예산: 500만원 → 목표 평가액 200만원
사용자 B 예산: 1,000만원 → 목표 평가액 400만원
```

### 6.2 지원할 예산 모드

#### A. 고정 전략예산

사용자가 전략에 투입할 총한도를 직접 입력한다.

```text
기본값: 5,000,000원
목표 평가액 = 고정 전략예산 × 목표비중
```

현재 사용자에게 가장 단순하고 권장되는 기본 모드다.

#### B. 현재 전략자산 기준

현재 현금과 BTC 평가액의 합을 전략자산으로 삼는다.

```text
전략자산 = 현금 + BTC 수량 × 업비트 참고가격
목표 평가액 = 전략자산 × 목표비중
조정 검토액 = 목표 평가액 - 현재 BTC 평가액
```

수익이나 손실로 계좌 규모가 변할 때 자동으로 비중을 맞추기 좋다.

#### C. 정기 납입 계획

초기예산과 월 추가금액을 입력한다.

```text
약정예산 = 초기예산 + 누적 추가납입
목표 평가액 = 약정예산 × 목표비중
```

추가납입 날짜와 금액은 사용자 브라우저에만 저장한다.

### 6.3 사용자 입력 항목

```text
예산 모드
전략예산
현재 현금
현재 BTC 수량
평균매입가(선택)
누적 납입·인출액(선택)
월 추가납입액(선택)
```

화면에는 다음 빠른 선택을 제공한다.

```text
100만원 / 300만원 / 500만원 / 1,000만원 / 직접입력
```

직접입력은 1원 단위 저장이 가능하되 화면 표시와 주문 검토액은 원 단위로 반올림한다. 예산 변경 전후 값을 사용자에게 명시하고, `저장`을 눌러야 영구 반영되도록 한다.

### 6.4 저장과 개인정보

- 기본 저장 위치: 브라우저 `localStorage`
- 서버·GitHub·공개 JSON으로 전송하지 않음
- `내 설정 내보내기`로 JSON 백업 가능
- `내 설정 가져오기`로 복원 가능
- `개인정보 초기화` 버튼 제공
- 공용 PC에서는 개인 수량 입력을 경고

### 6.5 예산 변경 규칙

예산을 바꾸면 다음 항목만 즉시 재계산한다.

```text
목표 원화 평가액
현재 대비 매수·매도 검토액
예상 BTC 수량
개인 포트폴리오 비중
```

다음 항목은 절대 바뀌지 않는다.

```text
시장 상태
목표비중
전략 수익률
백테스트 결과
신호 발생일
```

### 6.6 기본 500만원 예시

후보 비중표가 `0·20·40·60·80·100%`일 경우:

| 목표비중 | 목표 평가액 |
|---:|---:|
| 0% | 0원 |
| 20% | 1,000,000원 |
| 40% | 2,000,000원 |
| 60% | 3,000,000원 |
| 80% | 4,000,000원 |
| 100% | 5,000,000원 |

축소단계 후보:

| 목표비중 | 목표 평가액 |
|---:|---:|
| 75% | 3,750,000원 |
| 50% | 2,500,000원 |
| 25% | 1,250,000원 |
| 0% | 0원 |

이 비중은 모의운영 시작 후보이며 실전 확정값이 아니다.

## 7. 수익률 표시 정의

수익률 종류를 섞어 표현하지 않는다.

| 명칭 | 정의 | 공개/개인 |
|---|---|---|
| 전략 수익률 | 승인된 목표비중과 가상 체결을 적용한 자산곡선 수익률 | 공개 |
| BTC 단순보유 수익률 | 전략과 동일한 시작·종료일의 BTC 100% 보유 수익률 | 공개 |
| 초과수익률 | 전략 수익률 - 동일기간 BTC 단순보유 수익률 | 공개 |
| 현재 상태 수익률 | 현재 상태가 시작된 다음 실행가능 가격부터의 수익률 | 공개 |
| 최근 30일 수익률 | BTC 가격의 30일 수익률 | 공개 |
| 개인 평가손익률 | 사용자가 입력한 평균단가 대비 미실현 손익률 | 브라우저 로컬 |
| 개인 계좌수익률 | 현금·BTC·납입·인출을 반영한 개인 성과 | 브라우저 로컬 |

텔레그램 기본값은 다음 세 가지다.

```text
목표비중
전략 수익률 / BTC 단순보유 수익률
현재 상태 이후 수익률
```

개인 금액은 `BTC_BUDGET_KRW` GitHub Actions 변수나 Secret을 사용자가 별도로 설정한 경우에만 선택적으로 표시한다.

대시보드 수익률 카드에는 동일 기준일을 강제하고 다음 기간 선택을 제공한다.

```text
현재 상태 이후 / 30일 / 90일 / 1년 / 2년 / 2016년 이후 / 전체 검증기간
```

기간이 충분하지 않으면 `계산 불가`와 사유를 표시하며, 서로 다른 시작일의 수익률을 같은 표에서 직접 비교하지 않는다.

## 8. 반감기 필수 원칙

### 8.1 필수성

모든 배포 가능한 전략은 다음 정보를 가져야 한다.

```text
현재 블록 높이
현재 반감기 epoch
직전 반감기 블록과 시각
다음 반감기까지 남은 블록
사이클 진행률
직전 반감기 후 경과일
현재 블록 보조금
연환산 신규발행률
```

이 정보가 없거나 신뢰성 검증에 실패하면 신규 매수·매도 신호를 만들지 않고 `DATA_ERROR`로 전환한다.

### 8.2 사용 방식

반감기는 다음을 조절한다.

- 신규매수에 필요한 확인 강도
- 허용 가능한 최대 목표비중
- 과열·분배 신호의 민감도
- 핵심물량과 전술물량의 비율
- 신호 설명과 다음 조건

반감기는 단독 매매조건이 아니다. 가격추세·가치·온체인·위험영역 중 독립된 확인이 함께 있어야 한다.

### 8.3 무반감기 비교군

반감기 변수를 제거한 전략은 기여도 검증을 위한 연구용 ablation으로만 실행한다.

```text
halving_required = false
research_only = true
deployable = false
```

무반감기 전략이 백테스트에서 더 좋아도 사용자 승인 없이는 실전 배포하지 않는다.

## 9. 전략 평가 영역

비슷한 지표를 무작정 더하지 않고 영역별 상한을 둔다.

| 영역 | 목적 | 후보 정보 |
|---|---|---|
| 반감기·공급 사이클 | 현재 사이클의 구조적 위치 | 블록 진행률, 경과일, 발행률, 보조금 |
| 장기 추세 | 상승·하락 구조 확인 | 50·100·200일선, 20·40주선, 기울기, 돌파 |
| 가치·투매 | 장기 매집 가치 확인 | 고점대비 낙폭, 200일/200주 이격, MVRV, 실현가격, NUPL, Puell |
| 모멘텀·진입시점 | 분할매수·회복 시점 | RSI, PPO/MACD, 30·90일 수익률, 거래량, 볼린저, ATR |
| 과열·분배 위험 | 단계축소·매도 검토 | MVRV/NUPL 극단값, 주봉 RSI, 장기선 과대이격, 급등률 |
| 원화시장·교차검증 | 업비트 실행 위험 확인 | 김치프리미엄, USD/KRW 신호 합의, 데이터 괴리 |
| 보조 거시·파생 | 설명력 검증 | DXY, VIX, 실질금리, 유동성, 펀딩, 미결제약정 |

거시·파생·뉴스·감성 정보는 연구에서 증분효과가 확인되기 전까지 핵심 신호를 뒤집지 못한다.

MVRV에서 파생한 Realized Price와 NUPL은 서로 독립된 확인으로 세지 않는다. 현재 무료 Community catalog에서 확인되지 않은 SOPR·MVRV Z 등은 기본 비활성화하고, 화면에 결측 이유를 표시한다.

## 10. 상태 머신과 후보 목표비중

### 10.1 상태

| 상태 | 표시 | 후보 목표비중 | 의미 |
|---|---|---:|---|
| `DATA_ERROR` | 데이터 확인 필요 | 기존비중 유지 | 데이터가 불완전해 신규 행동 금지 |
| `WAIT` | 매수 대기 | 0% | 장기 기대수익 구간 아님 |
| `WATCH` | 관심 구간 | 0% | 일부 저가·투매 조건 접근 |
| `ACCUMULATE_1` | 1차 분할매수 | 20% | 독립된 투매·가치 조건 충족 |
| `ACCUMULATE_2` | 2차 분할매수 | 40% | 투매 지속·재시험·온체인 확인 |
| `CONFIRM_BUY` | 추세 확인 매수 | 60% | 저점구간 후 단기추세 회복 |
| `TREND_HOLD` | 보유·추가편입 | 80% | 장기추세 회복·유지 |
| `FULL_HOLD` | 최대 보유 | 100% | 사이클·추세·위험조건 모두 허용 |
| `REDUCE_1` | 1차 비중축소 | 75% | 과열 또는 분배 위험 상승 |
| `REDUCE_2` | 2차 비중축소 | 50% | 과열+추세약화 동시 확인 |
| `CORE_ONLY` | 핵심물량만 유지 | 25% | 전술물량 제거, 장기 핵심만 유지 |
| `EXIT` | 매도·대기 | 0% | 전량매도 전략에서 구조적 위험 확인 |
| `SHADOW_ONLY` | 모의운영 | 계산값만 표시 | 실제 주문 금지 |

후보 비중은 백테스트·민감도·모의운영 후 변경할 수 있다.

### 10.2 전이 원칙

- 하루에 여러 단계를 건너뛰지 않는 것이 기본이다.
- 예외적 데이터 복구 또는 승인된 긴급위험 조건만 단계 건너뛰기를 허용한다.
- 같은 방향의 신호가 일정 기간 지속되어야 전이한다.
- 반대신호 발생 후 재진입에는 냉각기간과 회복조건을 둔다.
- 단기 RSI 한 번으로 0%↔100% 전환하지 않는다.

## 11. 매수전략 후보

### 11.1 경로 A — 장기 투매 매집

다음 독립영역 중 최소 수를 충족할 때 1차·2차 매집을 검토한다.

```text
반감기 사이클 위치 확인
고점대비 대형 낙폭
200일선·200주선 대비 저평가
RSI·30일 수익률의 투매
MVRV·실현가격·NUPL의 저평가
거래량·SOPR의 손실실현
```

기존 연구 시작점:

```text
365일 고점 대비 하락률 <= -50%
AND 종가 / SMA200 <= 0.80
AND RSI14 <= 30
AND 30일 수익률 <= -15%
```

이 식은 그대로 확정하지 않고 온체인·반감기 영역을 추가해 주변 임계값을 비교한다.

### 11.2 경로 B — 저점 후 회복 확인

- 투매 발생 후 50일선 회복
- PPO 또는 MACD 히스토그램 개선
- 주봉 모멘텀 악화 중단
- MVRV·NUPL의 회복 또는 SOPR 1 재돌파

확인매수는 바닥보다 비싸게 살 수 있지만 첫 가짜바닥 위험을 줄이는 목적이다.

### 11.3 경로 C — 장기 상승추세 참여

- 종가가 200일선 또는 40주선 위로 회복
- 장기선 기울기 개선
- 돌파 후 재지지 또는 비영(非零) 밴드 유지
- 반감기 국면상 최대비중 허용

### 11.4 분할 원칙

- 첫 투매 신호에 전액 매수하지 않는다.
- 후보 기본단위는 전용예산의 20%다.
- 가격이 더 떨어졌다는 이유만으로 자동 물타기하지 않는다.
- 추가매수는 독립된 새 확인 또는 상태 지속을 요구한다.

## 12. 보유·축소·매도전략 후보

### 12.1 보유

다음 조건에서는 비중을 유지한다.

- 장기추세가 유지되고 과열 위험이 임계값 미만
- 단기 조정이지만 200일선·주봉 구조가 유지
- 반감기 국면상 신규매수는 제한되나 기존 보유를 줄일 근거가 부족

### 12.2 과열 기반 단계축소

반감기 후 중후반 국면에서 다음 독립영역이 여러 개 겹치면 25% 단위 축소를 검토한다.

```text
MVRV 또는 NUPL의 역사적 상위 극단
주봉 RSI 극단
가격의 200일선·200주선 과대이격
90·180일 수익률의 포물선 급등
업비트 프리미엄의 역사적 상위 극단
분배성 거래량·SOPR 변화
```

### 12.3 추세붕괴 기반 축소

- 주봉 종가가 장기 추세선 아래에서 지속
- 200일선 기울기 하락
- 중기 모멘텀 음전환
- 온체인 이익실현에서 손실실현 국면으로 전환

단기 급락 직후 저점에서 뒤늦게 전량매도하지 않도록 과열축소와 추세붕괴를 분리한다.

### 12.4 세 가지 매도정책 비교

1. `all_out`: 승인된 구조적 붕괴 시 0%
2. `tiered`: 100→75→50→25→0%
3. `core_tactical`: 핵심 25% 또는 승인된 핵심비중 유지, 전술만 조절

최종 정책은 같은 비용·같은 데이터·같은 검증구간으로 비교해 선택한다.

- 가상 체결: 다음 Upbit 실행가능 가격 + 비용
- 매일 신호·근거·목표비중·가상평가액 기록
- 상태변경 텔레그램 검증
- 누락·중복·오류 복구 검증
- 종료 후 전략·벤치마크·신호정확성·운영안정성 보고
- 자동으로 실전모드 전환하지 않음

## 18. 성공 기준

1. 예산을 변경해도 시장 신호와 목표비중이 변하지 않는다.
2. 같은 비중을 다른 예산에 적용하면 목표금액이 정확히 비례한다.
3. 전략·벤치마크·상태·개인 수익률이 서로 명확히 구분된다.
4. 모든 배포 가능한 신호에 반감기 컨텍스트가 포함된다.
5. 반감기 데이터 실패 시 신규 매매문구가 차단된다.
6. 가격·온체인·원화시장 중 어떤 영역이 판단에 기여했는지 설명된다.
7. 개인 정보가 공개 HTML·JSON·CSV·로그·artifact에 포함되지 않는다.
8. ETF 기능의 기존 회귀테스트가 모두 통과한다.
9. 30일 모의운영 동안 중복알림·미완성 일봉 사용·가상체결 미래참조가 없다.
10. 실전 전 최종 전략과 임계값을 사용자가 승인한다.
