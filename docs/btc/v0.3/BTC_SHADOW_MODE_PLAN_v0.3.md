# BTC Shadow Mode Plan — Quant Guardian

- 문서 버전: `0.3`
- 기준일: `2026-08-09`
- 상태: **모의운영 계획 / 실제 주문 금지**
- 기간: 최초 정상 배포 뒤 `30개 확정 UTC 일봉`

> Shadow mode의 목적은 수익을 증명하는 것이 아니라 데이터·상태판정·가상체결·차트·텔레그램이 실제 운영시간에 재현 가능하게 작동하는지 확인하는 것이다.

---

## 1. 시작 조건

다음을 모두 충족해야 Shadow day 1을 시작한다.

- 최신 로컬 GitHub 기준 commit SHA 기록
- 기존 ETF 테스트 통과
- BTC 단위테스트·통합테스트 통과
- Upbit·USD 가격·블록 높이 데이터 정상
- 반감기 context 계산 정상
- 최초 `daily.json`과 대시보드 생성 정상
- Telegram test channel 발송 정상
- 실제 주문 API 키 없음
- 사용자 화면에 `모의운영 — 실제 주문 금지` 표시

---

## 2. 시간 기준

```text
신호 일봉: UTC 00:00 ~ 다음 UTC 00:00
한국시간 일봉 마감: 09:00 KST
초기 예약실행 후보: 09:17 KST 매일
```

- 미완성 당일 캔들은 차트에 참고로 보일 수 있으나 신호에는 사용하지 않는다.
- 예약실행 지연 시 실제 수집시각과 대상 캔들 기준시각을 모두 기록한다.
- 09:17은 초기값이며 설정에서 변경 가능하다.

---

## 3. 가상 포트폴리오

### 3.1 공개 비교용

```text
초기자산 = 100
초기 BTC 비중 = 0%
초기 현금 비중 = 100%
```

예산에 영향을 받지 않는 정규화 수익률을 계산한다.

### 3.2 개인 예시용

```text
기본 가상예산 = 5,000,000원
사용자 변경 가능
```

개인 예산은 브라우저 안에서만 적용한다. 공개 Shadow 성과는 `100 기준`으로 유지한다.

### 3.3 가상 체결

- 신호는 확정 일봉 뒤에만 생성한다.
- 신호일 종가에 이미 체결했다고 가정하지 않는다.
- 다음 실행 가능한 Upbit 가격을 사용한다.
- 수수료와 슬리피지를 각각 설정값으로 차감한다.
- 매수·매도 최소 주문금액과 반올림을 적용한다.
- 가상 현금과 BTC 수량이 음수가 되어서는 안 된다.

## 5. 알림 정책

## 6. 데이터 장애 처리

| 등급 | 예 | 동작 |
|---|---|---|
| INFO | 보조 거시데이터 지연 | 마지막값 사용 여부를 표시, 핵심상태 유지 가능 |
| WARNING | 보조 온체인 1일 지연 | 해당 영역 비활성화, 새 비중확대 제한 검토 |
| CRITICAL | Upbit 확정일봉 누락 | 신규 행동 금지, `DATA_ERROR` |
| CRITICAL | 블록 높이 역행·불일치 | 반감기 필수조건 실패, 신규 행동 금지 |
| CRITICAL | 계산 결과 비중 범위 오류 | 배포 실패, Telegram 오류 알림 |

`DATA_ERROR`는 보유분 자동매도를 뜻하지 않는다. 마지막 정상 목표비중을 유지하고 새 주문 검토만 중단한다.

## 8. Shadow 합격 기준

### 8.1 필수 합격

- 30개 확정 일봉 처리 완료
- 미래참조 0건
- 동일 입력의 신호 재현율 100%
- 중복 Telegram 0건
- 개인 예산·보유량의 공개 산출물 유출 0건
- 반감기 context 누락 상태에서 신규 행동 0건
- 비중 범위 0~100% 위반 0건
- 음수 현금·음수 BTC 0건
- 기존 ETF 결과 회귀 0건
- 데이터 장애 시 명시적 오류표시 100%

### 8.2 권장 품질기준

- 예정일의 95% 이상에서 30분 안에 정상 결과 생성
- 소스 간 가격차·김치프리미엄 이상치가 모두 로그에 남음
- 상태변경 근거가 화면·Telegram·JSON에서 일치
- 사용자 예산 변경 후 목표금액 계산이 즉시 정확히 갱신
- 모바일 화면에서 핵심 카드가 첫 화면 안에 표시

수익률 플러스 여부는 Shadow 합격 조건이 아니다.

## 10. Live 전환 게이트

Shadow mode는 자동으로 live로 바뀌지 않는다.

```text
30일 종료
→ 종료보고서 검토
→ 전략·비중·알림 임계값 확정
→ 사용자 명시 승인
→ 별도 release tag
→ live advisory mode
```

Live도 자동주문은 하지 않는다.
