## 2. 사용자 선택형 예산 결정

### 2.1 신호와 개인금액을 분리한다

시장 엔진은 다음 두 값만 공개적으로 만든다.

```text
현재 상태
목표 BTC 비중
```

개인 브라우저가 목표비중을 사용자가 선택한 예산에 적용한다.

```text
목표 BTC 평가액 = 적용 예산 × 목표 BTC 비중
조정 검토액 = 목표 BTC 평가액 - 현재 BTC 평가액
```

예시:

```text
목표비중 40%
예산 500만원  → 목표 BTC 평가액 200만원
예산 800만원  → 목표 BTC 평가액 320만원
예산 1,000만원 → 목표 BTC 평가액 400만원
```

예산을 바꿔도 다음은 변하지 않는다.

- 시장 상태
- 목표비중
- 전략 수익률
- BTC 단순보유 수익률
- 백테스트
- 매수·보유·축소 조건

### 2.2 지원 예산 모드

| 모드 | 사용 목적 | 계산 기준 |
|---|---|---|
| 고정 전략예산 | BTC에 따로 배정한 한도를 유지 | 사용자가 입력한 고정금액 |
| 현재 계좌가치 | 수익·손실에 따라 실제 계좌 규모를 기준으로 재조정 | 현금 + BTC 현재평가액 |
| 적립식 예산 | 초기자금과 월 추가납입을 함께 관리 | 초기예산 + 누적납입 |

### 2.3 사이트 입력 방식

초기 화면은 다음을 제공한다.

```text
[100만원] [300만원] [500만원] [1,000만원] [직접입력]
예산 모드 선택
현재 BTC 수량
평균매입가(선택)
현금 잔액(선택)
```

- 기본 선택값은 500만원이다.
- `저장`을 누른 뒤에만 브라우저 로컬상태를 변경한다.
- `내보내기`, `가져오기`, `초기화` 기능을 제공한다.
- 공개 HTML·JSON·CSV·GitHub Actions 로그에는 개인값을 넣지 않는다.



### 3.2 개인 브라우저 카드

사용자가 보유정보를 입력한 경우에만 다음을 표시한다.

```text

현재 BTC 평가액
추가매수 또는 축소 검토액
미실현 손익
개인 단순수익률
```

거래내역과 입출금이 충분할 때만 TWR·XIRR을 별도 명칭으로 추가한다.

## 4. 텔레그램 예산 처리 결정

### 4.1 v1 기본값

자동 텔레그램에는 다음을 보낸다.

```text
현재 행동
목표비중
전략 수익률
동일기간 BTC 단순보유 수익률

반감기 위치
다음 행동 조건
데이터 상태
```

이 방식은 사이트에서 사용자가 예산을 바꾸어도 정확하게 유지된다.

### 4.2 선택형 목표금액

텔레그램에 목표금액도 필요할 경우 GitHub의 비공개 설정값을 별도로 둔다.

```text
BTC_BUDGET_KRW=5000000
```

메시지에는 다음과 같이 출처를 명시한다.

```text
텔레그램 설정 예산: 5,000,000원
목표비중: 40%
예산 기준 목표액: 2,000,000원
```

정적 GitHub Pages의 브라우저 `localStorage`를 GitHub Actions가 읽을 수 없으므로, 사이트 예산과 텔레그램 예산은 자동 동기화되지 않는다.

### 4.3 향후 선택지 — v1 범위 밖

Telegram 명령으로 예산을 바꾸는 기능은 다음이 필요하다.

```text
/budget 8000000
/status
/holding 0.035
```

이를 안전하게 구현하려면 인증된 사용자 확인, 비공개 상태저장소, 수정 이력, 오입력 취소가 필요하므로 v1에는 넣지 않는다. 실제 필요성이 확인된 뒤 별도 승인한다.

## 5. 반감기 필수 결정

### 5.1 계산 기준

반감기 국면은 달력상의 고정 날짜가 아니라 블록 높이로 계산한다.

```text
HALVING_INTERVAL = 210000
halving_epoch = floor(block_height / 210000)
blocks_since_halving = block_height mod 210000
cycle_progress = blocks_since_halving / 210000
blocks_to_next_halving = 210000 - blocks_since_halving
block_subsidy_btc = 50 / 2^halving_epoch
```

다음 반감기 예상일은 화면 참고용이며 매매 입력으로 사용하지 않는다.

### 5.2 실전 배포 게이트

- 반감기 데이터가 없으면 신규 신호를 만들지 않는다.
- 블록 높이가 역행하거나 소스 간 불일치가 허용범위를 넘으면 `DATA_ERROR`다.
- 반감기 하나만으로 매수·매도하지 않는다.
- 반감기는 가격·추세·온체인 신호의 의미와 요구확인 수를 조절한다.
- 무반감기 모델은 ablation 비교표에만 표시한다.

- 최신 로컬 GitHub 기준 commit SHA가 확인되지 않음
