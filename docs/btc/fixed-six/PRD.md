# Quant Guardian BTC Fixed Six · Clock Hybrid 1.1 — PRD

- 승인일: 2026-08-19
- 투자대상: Upbit `KRW-BTC` 현물
- 시작예산: 10,000,000원
- 자동주문: 없음

## 1. 목적

Bitcoin 반감기 블록 진행률만으로 사이클당 기본 매수 3회·매도 3회를 안내하고, 사용자가 Telegram에서 직접 Upbit 주문과 실제 잔고 동기화를 수행하는 개인용 투자 보조 시스템이다.

핵심 목표:

1. 가격예측 신호를 추가하지 않고 반감기 시계 규칙을 단순하게 유지한다.
2. 첫 매수 전에 자금 준비시간을 제공한다.
3. 매도는 36·37·38%의 각 임계값에 실제로 도달했을 때만 한 단계씩 실행한다.
4. 오래된 주문금액을 그대로 사용하지 않게 한다.
5. 기존 실사용 상태와 ISA 통합 메뉴를 보존한다.

## 2. 전략 규칙

### 2.1 매수

```text
62.5% 도달
→ 저점 관찰 알림만 1회

65% 도달
→ 다음 공식 월요일 1차 매수, BTC 목표 1/3
→ 다음 공식 월요일 2차 매수, BTC 목표 2/3
→ 다음 공식 월요일 3차 매수, BTC 목표 100%
```

매수 2·3차는 기존과 같이 월요일마다 진행하되, 이전 주문의 잔고 동기화가 완료돼야 한다.

### 2.2 매도

```text
매수한 epoch의 다음 epoch 35% 도달
→ 고점 위험경고만 1회

36% 도달 + 이전 단계 완료
→ 다음 공식 월요일 1차 매도, BTC 목표 2/3

37% 도달 + 1차 완료
→ 다음 공식 월요일 2차 매도, BTC 목표 1/3

38% 도달 + 2차 완료
→ 다음 공식 월요일 3차 매도, BTC 목표 0%
```

한 공식 점검에서 여러 단계를 생성하지 않는다. 38%를 이미 넘었어도 1차가 미완료이면 1차 주문안만 만든다.

## 3. 첫 매수 자금준비

현재 블록 높이에서 10분/블록으로 65% 도달시각을 추정하고, 그 뒤 첫 월요일 09:17 KST를 예상 1차 매수일로 계산한다.

- 약 5영업일 전 알림
- 약 3영업일 전 알림

표시 항목:

- 예상 65% 도달시각
- 예상 첫 공식 매수일
- 남은 블록
- 준비할 총 원화
- 1차 목표 주문액 근사

주말만 제외한 근사 영업일이며 한국 공휴일은 반영하지 않는다. 예상일 변경 자체로 주문을 생성하지 않는다.

## 4. 체결 지연 관리

주문안에 다음 버튼을 제공한다.

- 주문 완료·잔고 동기화
- 현재 금액 다시 계산
- 30분 뒤 다시 알림
- 주문안 취소

규칙:

- 24시간 이후: 알림 당시 금액 사용 금지, 재계산 권고
- 3일 이후: 오래된 주문안 주의
- 7일 이후: 기존 금액 사용 금지, 재계산 또는 취소

재계산은 같은 단계와 목표비중을 최신 가격·마지막 동기화 잔고에 적용한다. 취소는 단계를 완료시키지 않는다.

## 5. 예산·추가입금

- 첫 매수 전 시작예산 변경 가능
- 매수 중 추가입금은 남은 단계에 반영
- HOLD 중 현재 사이클 적용은 다음 월요일 보정매수 1회
- 다음 사이클 보관 선택 가능
- 매도 중 추가입금은 다음 사이클 대기자금

## 6. 잔고 동기화

각 주문 후:

1. 실제 Upbit BTC 총수량 입력
2. 실제 원화잔액 입력
3. 최종 확인
4. 단계 완료 및 다음 주문 가능

pending sync가 남아 있으면 다음 주문을 만들지 않는다.

## 7. Telegram·스케줄

- 15분 polling: 매시 02·17·32·47분
- 공식 행동: 월요일 09:17 KST 이후 첫 실행
- 월간보고: 매월 첫 월요일
- BTC·ISA 입력은 통합 봇 한 곳에서 처리
- BTC·ISA 상태파일은 분리

## 8. 상태 보호

기존 `schema 4 / btc-fixed-six-upbit-telegram-1.0`을 `schema 5 / btc-fixed-six-clock-hybrid-1.1`로 안전하게 변환한다.

반드시 보존:

- BTC·KRW 잔고
- 납입원금·대기자금·MDD history
- phase·완료 단계
- pending operation·pending sync
- Telegram update 위치·메뉴버전
- 감사로그

알 수 없는 버전은 자동 초기화하지 않는다.

- 레버리지·선물·공매도

## 10. 인수 기준

1. 62.49%에는 관찰 알림이 없고 62.5%에서 1회만 발생한다.
2. 65% 미만에는 1차 매수 주문이 없다.
3. 예상 첫 매수 5·3영업일 전 알림이 epoch당 각각 최대 1회다.
4. 35%에는 경고만 있고 매도 주문은 없다.
5. 36·37·38%가 각 매도 단계를 순서대로 잠금 해제한다.
6. 임계값을 크게 넘어도 한 공식 점검에서 한 단계만 생성한다.
7. pending sync가 다음 단계를 차단한다.
8. 주문안 재계산·취소가 단계를 잘못 진행시키지 않는다.
9. legacy 상태 마이그레이션이 계좌·Telegram 상태를 보존한다.
10. 전체 회귀테스트가 통과하고 자동주문이 존재하지 않는다.
