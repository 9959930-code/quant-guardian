# Quant Guardian BTC Fixed Six — PRD

- 최초 기준일: 2026-08-11
- clock-hybrid 개편: 2026-08-19
- 상태: 사용자 승인 운영안
- 전략 버전: `btc-fixed-six-clock-hybrid-1.1`
- 투자대상: Upbit `KRW-BTC` 현물
- 자동주문: 없음

## 1. 제품 목적

Bitcoin 반감기 블록 진행률로 넓은 매수·보유·매도 구간을 정하고, Telegram에서 사용자가 직접 Upbit 주문을 실행하도록 안내한다. 사이클당 기본 매매는 매수 3회·매도 3회로 제한하며, 주문 후 실제 잔고를 동기화해야 다음 단계로 진행한다.

## 2. 확정 전략

```text
현재 epoch 진행률 62.5%
→ 저점 관찰 알림 1회
→ 주문 없음

현재 epoch 진행률 65%
→ 다음 공식 월요일 1차 매수: BTC 33.3%
→ 다음 주 월요일 2차 매수: BTC 66.7%
→ 다음 주 월요일 3차 매수: BTC 100%

보유 중 중간 리밸런싱 없음

매수한 epoch의 다음 epoch 진행률 35%
→ 고점 위험경고 1회
→ 주문 없음

다음 epoch 진행률 36%
→ 다음 공식 월요일 1차 매도: BTC 66.7%

진행률 37%
→ 이전 단계 완료·잔고동기화 후 다음 공식 월요일 2차 매도: BTC 33.3%

진행률 38%
→ 이전 단계 완료·잔고동기화 후 다음 공식 월요일 3차 매도: BTC 0%
```

- 실제 판정은 부동소수점 진행률보다 epoch 내 블록 오프셋을 우선한다.
- 임계값을 한 번에 크게 넘어도 한 공식 점검에서 한 단계만 안내한다.
- 36%에서 1차 매도를 완료했더라도 37%에 도달하지 않으면 2차 매도를 만들지 않는다.
- 레버리지·공매도·선물은 사용하지 않는다.
- 가격·RSI·MVRV·변동성은 중간 매매조건으로 사용하지 않는다.

## 3. 예산과 추가입금

- 기본 시작예산: `10,000,000원`
- 첫 매수 전에는 Telegram에서 변경할 수 있다.
- 분할매수 도중 추가입금은 남은 단계 목표금액에 반영한다.
- 3차 매수 후 현재 사이클 적용을 선택하면 다음 월요일 보정매수 1회가 발생한다.
- 매도 중 추가입금은 다음 사이클 대기자금으로만 보관한다.

## 4. 주문과 잔고동기화

각 주문 안내에는 다음 버튼을 표시한다.

- `주문 완료 · 잔고 동기화`
- `현재가로 주문안 재계산`
- `30분 뒤 다시 알림`

잔고동기화 순서:

1. 실제 Upbit BTC 총수량 입력
2. 실제 원화잔액 입력
3. 최종 확인
4. 해당 매수·매도 단계 완료 처리

pending sync가 남아 있으면 다음 단계 주문을 만들지 않는다.

## 5. 체결 지연 안전장치

- 알림 후 24시간: 현재가와 현재 저장잔고로 주문검토액을 자동 재계산한다.
- 3일: 체결지연 주의를 표시하고 다시 계산한다.
- 7일: 기존 주문안을 만료 표시한다.
- 주문안 만료는 전략 단계를 완료하거나 취소하지 않는다.
- 이미 체결했다면 실제 잔고를 동기화하고, 아직 체결하지 않았다면 현재가 재계산 버튼으로 새 주문안을 발급한다.
- 알림 당시 원화금액을 장기간 그대로 사용하지 않는다.

## 6. Telegram 사용자 경험

통합 메뉴:

- `BTC 상태`
- `ISA 상태`
- `BTC 잔고 동기화`
- `ISA 잔고 동기화`
- `BTC 추가입금`
- `BTC 시작예산`
- `대기 작업`
- `도움말`

BTC와 ISA는 같은 봇을 사용하지만 상태파일과 잔고동기화 흐름은 분리한다.

## 9. 상태 호환성

기존 `btc-fixed-six-upbit-telegram-1.0`, schema 4 상태는 schema 5로 마이그레이션한다.

반드시 보존할 값:

- 현금·BTC 수량
- 총 납입원금과 대기자금
- 현재 phase와 cycle epoch
- 완료된 매수·매도 단계
- pending sync·입력대기·확인대기
- 평가액 이력과 MDD
- Telegram update offset와 통합 메뉴 버전

알 수 없는 상태버전은 초기화하지 않고 오류로 중단한다.

## 11. 인수 기준

1. 62.5%는 알림만 보내고 주문을 만들지 않는다.
2. 65% 미만에서는 매수 주문이 없다.
3. 65% 이후 매수는 1/3 → 2/3 → 100%다.
4. 다음 epoch 35%는 경고만 보내고 주문을 만들지 않는다.
5. 36%·37%·38%에서 각각 한 단계만 매도한다.
6. 이전 임계값 단계와 잔고동기화가 완료되지 않으면 다음 단계가 없다.
7. 24시간·3일·7일 체결지연 안전장치가 중복 없이 동작한다.
8. 기존 schema 4 상태의 자산·단계·pending 상태가 보존된다.
9. 자동주문 API 호출이 존재하지 않는다.
10. BTC·ISA·기존 대시보드 전체 회귀테스트가 통과한다.
