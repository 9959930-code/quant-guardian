# BTC 고정 6회 clock-hybrid Telegram 운영방법

## 1. 현재 기본값

```text
전략: btc-fixed-six-clock-hybrid-1.1
거래소: Upbit KRW-BTC 현물
시작예산: 10,000,000원
주문: 사용자가 직접 실행
자동주문: 없음
```

## 2. Telegram 메뉴

- `BTC 상태`
- `ISA 상태`
- `BTC 잔고 동기화`
- `ISA 잔고 동기화`
- `BTC 추가입금`
- `BTC 시작예산`
- `대기 작업`
- `도움말`

BTC와 ISA 동기화는 서로 다른 상태파일에 반영된다.

## 3. 첫 매수 자금준비 알림

프로그램은 현재 블록 높이에서 `10분/블록`으로 65% 임계블록 도달시각을 추정하고, 그 이후 첫 월요일 09:17 KST를 예상 1차 매수 점검일로 계산한다.

- 약 5영업일 전: 첫 자금준비 알림
- 약 3영업일 전: 최종 자금준비 알림

알림에는 다음을 표시한다.

- 예상 65% 도달시각
- 예상 첫 공식 매수 점검일
- 65%까지 남은 블록
- 현재 BTC 가격
- 준비할 총 원화
- 1차 목표 주문액 근사

영업일은 주말만 제외한 근사치이며 한국 공휴일은 별도 반영하지 않는다. 블록 생성속도가 달라지면 예상일도 바뀔 수 있다. 정상적으로 예상일이 유지되면 약 5일·3일 전에 오지만, 추정이 갑자기 이동하면 4일 또는 2일에 근사 알림으로 올 수 있다. 각 알림은 epoch당 한 번만 오며 자동이체·자동주문은 없다.

## 4. 전략 알림

### 62.5% 저점 관찰

```text
🟢 BTC 저점 관찰 구간 진입
아직 매수 주문은 없음
65%까지 남은 블록 수 표시
```

### 65% 매수

65% 임계블록 도달 후 다음 공식 월요일 09:17 KST에 1차 주문안이 온다. 이후 잔고동기화를 완료한 경우에만 다음 월요일 2차·3차 매수로 진행한다.

### 다음 epoch 35% 고점 위험경고

```text
🟠 BTC 고점 위험구간 진입
아직 매도 주문은 없음
36%까지 남은 블록 수 표시
```

### 36·37·38% 매도

- 36% 도달 후 공식 월요일: BTC 2/3 유지
- 37% 도달 및 1차 완료 후 공식 월요일: BTC 1/3 유지
- 38% 도달 및 2차 완료 후 공식 월요일: BTC 0%

37%에 도달하지 않았다면 다음 월요일이 와도 2차 매도는 만들지 않는다. 임계값을 여러 개 넘었더라도 한 번에 한 단계만 안내한다.

## 5. 주문 알림을 받았을 때

1. Telegram 주문검토액 확인
2. 가능하면 알림 당일 Upbit에서 직접 주문
3. `주문 완료 · 잔고 동기화` 선택
4. 실제 BTC 총수량 입력
5. 실제 원화잔액 입력
6. 최종 확인

동기화 완료 전에는 다음 단계가 보류된다.

## 6. 체결이 늦어진 경우

### 24시간 경과

현재가와 저장잔고를 기준으로 주문검토액을 자동 재계산해 다시 보낸다. 최초 알림의 원화금액은 사용하지 않는다.

### 3일 경과

체결지연 주의 알림과 재계산 주문안이 온다. 매도 주문은 특히 가능한 한 빨리 처리한다.

### 7일 경과

기존 주문안이 만료 표시된다.

- 이미 주문함: `주문 완료 · 잔고 동기화`
- 아직 주문하지 않음: `현재가로 주문안 재계산`

만료돼도 단계가 자동 취소되거나 건너뛰지 않는다. pending sync가 유지되므로 중복 주문안은 생성되지 않는다.

## 7. 추가입금

- 분할매수 전·도중: 남은 매수 목표금액에 반영
- 3차 매수 후 현재 사이클 적용: 다음 월요일 보정매수 1회
- 다음 사이클 보관: 현재 사이클에는 투자하지 않음
- 분할매도 중: 다음 사이클 대기자금으로만 보관

## 8. 알림 주기

- 15분마다 시스템·Telegram 입력 점검
- 정상 평상시에는 무알림
- 예상 첫 매수 약 5영업일 전·3영업일 전 자금준비 알림
- 공식 주문 판단: 월요일 09:17 KST 이후 첫 실행
- 월간 상태보고: 매월 첫 번째 월요일
- 블록 이벤트: 62.5%, 65%, 반감기, 다음 epoch 35%
- 데이터 오류·복구 알림

## 9. 수동 실행

GitHub Actions에서 `BTC + ISA Portfolio Telegram`을 선택한다.

- `force_status=true`: BTC 상태보고
- `force_isa_status=true`: ISA 상태보고
- `reset_state=true`: BTC 상태 초기화
- `reset_isa_state=true`: ISA 상태 초기화

초기화는 실제 계좌와 프로그램 상태를 다시 맞춰야 할 때만 사용한다. 기존 schema 4 상태는 정상 실행 시 자동으로 schema 5로 마이그레이션되므로 초기화할 필요가 없다. 이미 schema 5인 상태에는 자금준비 알림 이력 필드만 안전하게 추가되며 BTC·KRW 잔고와 pending 작업은 유지된다.

## 10. 주의사항

- Telegram 알림은 주문을 자동 실행하지 않는다.
- 5·3영업일 알림은 블록속도와 주말 기준의 예상치다.
- 알림 당시 가격과 실제 체결가격은 다를 수 있다.
- GitHub 예약작업은 수분 이상 지연될 수 있다.
- 36·37·38% 매도는 과거 업비트 두 사이클에서 기존안보다 좋았지만 미래 급락에서는 늦은 매도가 불리할 수 있다.
- MDD는 상태조회와 월간보고에서 확인하며 자동 손절 조건으로 사용하지 않는다.


## 2026-09-05 지연 점검 보완

공식 월요일을 놓쳤다면 현재 주만 보충 점검한다. 화요일 이후 주문안은 같은 사이클·같은 단계 조건이 월요일 09:17 이전에 관측됐다는 기록이 있을 때만 만든다. 늦게 처음 관측한 임계값을 소급 충족으로 가정하지 않으며, 불확실하면 다음 공식 월요일로 보류한다. 한 번에 한 단계·pending sync 차단·현재가 재계산은 유지한다.

5일 알림을 놓치고 3일 알림을 먼저 전송했다면 5일 알림을 나중에 추가로 보내지 않는다. 준비일은 여전히 공휴일을 제외하지 않은 월~금 근사다.
