# BTC 고정 6회 Clock Hybrid 1.1 Telegram 운영방법

## 1. 기본값

```text
거래소: Upbit KRW-BTC 현물
시작예산: 10,000,000원
주문: 사용자가 직접 실행
자동주문: 없음
공식 행동 점검: 월요일 09:17 KST
Telegram 입력·블록 점검: 15분 간격
```

## 2. 전략 흐름

```text
62.5%  저점 관찰 알림만
65%    1차 매수 조건
다음 월요일 1차 → 다음 주 2차 → 다음 주 3차 매수

다음 epoch 35%  고점 위험경고만
36%    1차 매도 조건, BTC 2/3 목표
37%    2차 매도 조건, BTC 1/3 목표
38%    3차 매도 조건, BTC 0% 목표
```

매도 단계는 3주 연속으로 자동 진행하지 않는다. 이전 단계의 잔고 동기화가 끝났고 다음 블록 임계값에도 도달해야 다음 공식 월요일에 새 주문안이 생성된다. 38%를 한 번에 지나도 한 공식 점검에서는 한 단계만 생성한다.

## 3. 첫 매수 자금준비 알림

프로그램은 현재 블록 높이에서 10분/블록으로 65% 도달시각을 추정하고, 그 뒤 첫 월요일 09:17을 예상 1차 매수일로 계산한다.

- 약 5영업일 전: 첫 자금준비 알림
- 약 3영업일 전: 최종 자금준비 알림

알림에는 다음을 표시한다.

- 예상 65% 도달시각
- 예상 첫 공식 매수일
- 65%까지 남은 블록
- 준비할 총 원화
- 1차 목표 주문액 근사

블록 생성속도에 따라 날짜가 달라질 수 있다. 주말만 제외하는 근사 영업일이며 한국 공휴일은 별도 반영하지 않는다. 이 알림은 자금이체나 주문을 실행하지 않는다.

## 4. Telegram 메뉴

통합 메뉴에서 BTC 기능은 다음을 사용한다.

- `₿ BTC 상태`
- `🔄 BTC 잔고 동기화`
- `➕ BTC 추가입금`
- `💰 BTC 시작예산`
- `⏳ 대기 작업`
- `❓ 도움말`

ISA 상태와 ISA 잔고 동기화는 별도 상태파일을 사용하며 BTC 단계에 영향을 주지 않는다.

## 5. 주문 알림을 받았을 때

주문안 아래에는 다음 버튼이 표시된다.

- `✅ 주문 완료 · 잔고 동기화`
- `🔄 현재 금액 다시 계산`
- `⏰ 30분 뒤 다시 알림`
- `❌ 주문안 취소`

### 정상 체결

1. Telegram의 목표비중과 주문 검토액 확인
2. Upbit에서 직접 주문
3. `주문 완료 · 잔고 동기화` 선택
4. 현재 BTC 총수량 입력
5. 현재 원화잔액 입력
6. 최종 확인

잔고 동기화가 끝나기 전에는 다음 단계가 진행되지 않는다.

### 체결이 늦어진 경우

- 24시간 경과: 알림 당시 금액을 사용하지 않고 `현재 금액 다시 계산`
- 3일 경과: 오래된 주문안 주의
- 7일 경과: 기존 주문금액 사용 금지, 재계산 또는 취소

재계산은 최신 BTC 가격과 마지막 동기화 잔고로 같은 단계의 목표비중 주문액을 다시 만든다. 전략 단계는 진행되지 않는다.

### 주문하지 않기로 한 경우

`주문안 취소`를 누르면 pending sync만 제거한다. 단계 완료로 기록하지 않으며, 조건이 계속 유효하면 다음 공식 월요일에 다시 판단한다.

## 6. 추가입금

### 분할매수 전 또는 도중

- 금액 입력
- 확인 버튼 선택
- 남은 매수 목표금액에 반영

### 3차 매수 완료 후

- `현재 사이클에 적용`: 다음 공식 월요일 보정매수 1회
- `다음 사이클에 보관`: 현재 사이클에는 투자하지 않음

### 분할매도 중

다음 사이클 대기자금으로만 보관한다.

## 7. 알림 종류

### 행동이 없는 사전 알림

- 1차 매수 예상 5영업일 전 자금준비
- 1차 매수 예상 3영업일 전 자금준비
- 62.5% 저점 관찰
- 35% 고점 위험경고
- 실제 반감기 발생

### 주문 검토 알림

- 65% 이후 1·2·3차 매수
- 다음 epoch 36·37·38% 1·2·3차 매도
- HOLD 중 현재 사이클 추가입금 보정매수

### 운영 알림

- 주문 후 잔고동기화 30분 재알림
- 이후 매일 09:17 미완료 알림
- 데이터 오류·복구
- 매월 첫 번째 월요일 상태보고

## 8. 상태 마이그레이션

첫 Clock Hybrid 1.1 실행에서 기존 schema 4 상태를 schema 5로 변환한다.

보존 항목:

- 시작예산·총 납입원금
- BTC 수량·원화잔액·다음 사이클 대기자금
- peak·MDD·history
- 현재 phase와 완료 단계
- pending operation·pending sync
- Telegram last update ID와 통합 메뉴 버전
- 감사로그

새로 추가되는 항목:

- 62.5% 관찰 완료 epoch
- 5·3영업일 자금준비 알림 완료 키
- 새 전략·스키마 버전

알 수 없는 상태 버전은 자동으로 1,000만원·0 BTC로 초기화하지 않는다. 오류를 내고 기존 파일을 보존한다.

## 9. 수동 실행

GitHub Actions에서 `BTC + ISA Portfolio Telegram`을 선택한다.

- `force_status=true`: BTC 상태보고
- `force_isa_status=true`: ISA 상태보고
- `reset_state=true`: BTC 상태 초기화
- `reset_isa_state=true`: ISA 상태 초기화

초기화 입력은 실제 계좌와 프로그램 상태를 다시 맞춰야 할 때만 사용한다.

## 10. 주의사항

- 자동주문·출금 기능은 없다.
- 5·3영업일 알림은 블록속도 추정치이며 확정 일정이 아니다.
- 실제 주문 전에는 현재 가격과 목표비중을 다시 확인한다.
- 36·37·38% 규칙은 과거 Upbit 완결 사이클 두 개에서 기존 규칙보다 좋았지만 미래를 보장하지 않는다.
- 보유기간의 큰 낙폭은 그대로 감수한다.
