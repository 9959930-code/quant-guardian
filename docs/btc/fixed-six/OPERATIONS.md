# BTC 고정 6회 Telegram 운영방법

## 1. 현재 기본값

```text
거래소: Upbit KRW-BTC 현물
시작예산: 10,000,000원
현재 BTC: 0 BTC
주문: 사용자가 직접 실행
자동주문: 없음
```

## 2. Telegram 메뉴

- `상태 보기`
- `추가입금`
- `잔고 동기화`
- `시작예산 변경`
- `대기 작업`
- `도움말`

명령어를 외울 필요가 없다. `/status`, `/deposit`, `/sync`, `/budget`은 보조 수단으로만 남긴다.

## 3. 주문 알림을 받았을 때

1. Telegram의 주문 검토액 확인
2. Upbit에서 직접 주문
3. `주문 완료 · 잔고 동기화` 버튼 선택
4. BTC 수량 입력
5. 원화 잔액 입력
6. 확인 화면에서 `확정`

동기화를 하지 않으면 30분 뒤, 이후 매일 09:17에 다시 알려주며 다음 단계는 진행하지 않는다.

## 4. 추가입금

### 분할매수 전 또는 도중

- 금액 입력
- 확인 버튼 선택
- 남은 매수 목표금액에 반영

### 3차 매수 완료 후

버튼 중 하나를 선택한다.

- `현재 사이클에 적용`: 다음 월요일 보정매수 1회
- `다음 사이클에 보관`: 현재 사이클에는 투자하지 않음

### 분할매도 중

- 다음 사이클 대기자금으로만 보관

## 5. 예산 변경

첫 매수 전에는 `시작예산 변경` 메뉴로 수정할 수 있다. 첫 매수 후에는 시작예산을 재설정하지 않고 `추가입금`을 사용한다.

## 6. 알림 주기

### 평상시

- 15분마다 시스템·Telegram 입력 점검
- 정상 상태면 Telegram 무알림

### 매수·매도 3주 기간

- 매주 월요일 09:17 KST 전후 행동 알림

### 장기 보유·현금대기

- 매월 첫 번째 월요일 월간 상태보고

### 특별 알림

- 반감기 진행률 65% 도달
- 실제 반감기 발생
- 반감기 후 진행률 35% 통과
- 데이터 오류 및 복구

24시간 가격 급변과 MDD 단계별 실시간 알림은 보내지 않는다. MDD는 `상태 보기`와 월간보고에만 표시한다.

## 7. 왜 09:17인가

Upbit UTC 일봉은 한국시간 09:00에 경계가 바뀐다. 17분은 데이터 반영 여유와 GitHub Actions 정각 혼잡 회피를 위한 운영값이며 투자지표 의미는 없다.

## 8. 수동 실행

GitHub Actions에서 `BTC Fixed Six-Trade Telegram`을 선택한다.

- `force_status=true`: 즉시 상태보고
- `reset_state=true`: 10,000,000원·0 BTC로 초기화

초기화는 실제 계좌와 프로그램 상태를 맞춰야 할 때만 사용한다.

## 9. 주의사항

- Telegram 알림은 주문을 자동 실행하지 않는다.
- 실제 주문 후 잔고 동기화 전에는 다음 단계가 보류된다.
- GitHub 예약작업은 수분 이상 지연될 수 있다.
- 고정 6회 전략은 보유 중 큰 낙폭을 그대로 감수한다.
- 과거 수익률은 미래 수익을 보장하지 않는다.
