# BTC v0.7 Upbit Telegram 운영안

- 전략: `vol40 위험균형형`
- 투자예산 시작값: `5,000,000원`
- 최초 보유량: `0 BTC`
- 주문: 사용자가 Upbit에서 직접 실행
- 자동주문: 없음

## 전략 규칙

```text
보유구간:
반감기 epoch 진행률 65% 이상
또는 다음 epoch 진행률 35% 이하

보유구간 밖:
BTC 목표비중 0%

보유구간 안:
BTC 목표비중 = min(100%, 40% / 최근 63일 연환산 변동성)

리밸런싱:
매주 일요일 UTC 확정 종가로 판단
현재 실제비중과 목표비중의 차이가 10%p 이상일 때 한 번에 조정
최종 목표 0%에서는 전량매도
```

프로그램은 500만원·0 BTC에서 시작한 `전략 추종모형`을 GitHub Actions cache에 보존한다. 실제 Upbit 체결가격, 입출금, 수수료 차이로 실제 계좌와 추종모형이 달라질 수 있으므로 Telegram의 목표 BTC 평가액을 기준으로 사용자가 직접 확인한다.

## 알림 시각

GitHub Actions 예약:

```text
매일 00:17 UTC
매일 09:17 KST
```

GitHub 예약작업 특성상 실제 도착은 수분 이상 늦을 수 있다.

## 전송 규칙

### 최초 실행

- 이전 상태 cache가 없으면 요일과 관계없이 초기 등록 메시지 1회 전송
- 2026-08-11 첫 예약실행에서 초기 메시지를 보내도록 설계

### 매주 월요일

- 일요일 UTC 일봉 확정 후 주간 매매판단 전송
- 행동: 신규매수 / 추가매수 / 보유 / 비중축소 / 전량매도 / 현금대기
- 목표비중과 500만원 시작 추종계좌의 목표 평가액 표시

### 매월 첫 번째 월요일

- 주간 메시지에 최근 약 30일 수익률, 누적수익률, 최대낙폭을 함께 표시
- 월간 메시지를 별도로 중복 발송하지 않음

### 매일 데이터 점검

정상이고 월요일이 아니면 메시지를 보내지 않는다.

다음 상황에서는 즉시 메시지를 보낸다.

- Upbit 확정 일봉 오류 또는 지연
- 두 블록 높이 공급자 검증 실패
- 오류가 정상으로 복구됨

동일한 오류가 지속되면 매일 반복 발송하지 않되, 월요일에는 오류 상태를 다시 알린다.

## GitHub Secrets

기존 ETF Telegram 예약실행 로그에서 다음 Secret이 실제로 설정되어 있고 알림 전송에 성공한 것을 확인했다.

```text
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
```

비밀값 자체는 코드나 로그에 저장하지 않는다.

## 수동 실행

GitHub Actions에서 `BTC v0.7 Upbit Advisory`를 선택한다.

- `send_telegram=false`: 계산·테스트만 수행
- `send_telegram=true`: 계산 결과를 Telegram으로 전송
- `reset_model=true`: 추종모형을 500만원·0 BTC로 초기화

실제 거래 후 추종모형과 Upbit 계좌 차이가 커졌을 때만 초기화를 사용한다.

## 안전 원칙

- 자동주문 API를 사용하지 않는다.
- 반감기 또는 Upbit 핵심 데이터가 없으면 새 판단을 중단한다.
- BTC 목표비중은 0~100% 범위로 제한한다.
- 레버리지와 공매도를 사용하지 않는다.
- v0.7 백테스트 결과는 미래 수익을 보장하지 않는다.
